# Агенты на экзамене 1С:Специалист

ИИ-агент (Codex или Claude Code) решает официальный пример билета экзамена
«1С:Специалист по платформе», а стенд проверяет решение в настоящей 1С: загружает
конфигурацию, прогоняет 23 сценария по 65 требованиям билета и считает штрафы
по каталогу ошибок 1С. Оценку ставит программа по заранее заданным правилам, не ИИ.

Замер делается на вашем компьютере, результат отправляется PR и попадает в общий рейтинг.

Официальный исходник 1С включён в репозиторий: [ATT83PL.rtf](sources/1c/ATT83PL.rtf)
и [точный текст с номерами строк](sources/1c/ATT83PL.txt).
[Происхождение и SHA-256](sources/1c/provenance.json) позволяют проверить их независимо;
скачивать эти файлы отдельно после клонирования не нужно.

## Что нужно заранее

- **Python 3.11+** и **Git**;
- **платформа 1С:Предприятие 8.3** с активированной лицензией (рекомендуется 8.3.27);
- подписка **ChatGPT** с доступом к Codex или подписка **Claude**;
- отдельный компьютер или виртуальная машина с демобазами: агент работает в командной
  строке этой учётной записи.

Остальное — GitHub CLI, Node.js, сам агент, вход в аккаунты, настройку 1С и проверку грейдера —
стенд проверит сам и предложит сделать кнопками.

## Как сделать замер

```sh
git clone https://github.com/zeegin/1c-agent-exam-benchmark.git
cd 1c-agent-exam-benchmark
```

Запустите `start-demo.cmd` (Windows) или `./start-demo.sh` (macOS/Linux). Откроется
http://127.0.0.1:8879/ — страница «Замер»:

1. **Готовность стенда.** Пройдите шаги сверху вниз, пока все обязательные не станут ✓.
   Проверка грейдера делается один раз и занимает несколько минут.
2. **Запуск экзамена.** Выберите модель, окружение агента и лимит времени, нажмите
   «Начать экзамен». Страницу можно закрыть — экзамен продолжится.
3. **Отправка.** После оценки нажмите «Отправить в рейтинг», проверьте, что уйдёт в PR,
   и подтвердите. PR создаётся в вашем форке через GitHub CLI.

Подробно, с объяснением каждого шага: [docs/COMMUNITY.md](docs/COMMUNITY.md).
Поручение для ИИ-агента, который проводит замер за вас: [docs/AGENT_RUN.md](docs/AGENT_RUN.md).

## Что уходит в PR и что остаётся у вас

В PR: исходники решения (XML/BSL), DT, собранная из них, оценка и её расшифровка, модель,
агент, харнес, лимит, ОС, процессор и память, версия 1С, ваше имя и login GitHub.

Не уходят: вход в Codex или Claude, лицензия 1С, ключи, сырые журналы, имя пользователя ОС.
Всё локальное хранится в `.local/` и в Git не попадает.

## Свой харнес

Харнес — набор инструментов агента (MCP-сервер, skills). Каждый описан файлом
`harnesses/<id>.json` и готовится на странице «Замер» кнопкой «Подготовить».
Как добавить свой: [docs/harnesses.md](docs/harnesses.md).

## Ограничения

- Пример билета опубликован, модель могла его видеть. Это проверка решения известной
  задачи, а не неизвестного билета.
- Часть пунктов каталога штрафов пока не проверяется; тогда показывается верхняя граница
  балла («не выше …»), и такой результат не получает места в рейтинге.
- На Windows нет песочницы: результаты помечаются как неизолированные.
- Оценка стенда — не официальная аттестация фирмы 1С.

Что именно проверяется и что получает агент — раздел «Методика» на локальном сайте.
